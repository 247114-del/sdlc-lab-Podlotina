1. Планування

Мета продукту: Користувач повинен мати можливість швидко конвертувати грошові суми з однієї валюти в іншу, самостійно вказуючи актуальний курс обміну без прив’язки до інтернету чи банківських API.

2. Аналіз вимог (User Stories)

1. Як користувач, я хочу ввести суму та обрати напрямок конвертації (наприклад, з USD у UAH), щоб отримати точний результат перерахунку (Must have).
2. Як користувач, я хочу вручну ввести поточний курс валюти, щоб розраховувати суми за моїм власним або вигідним мені курсом обмінника (Must have).
3. Як користувач, я хочу натиснути одну кнопку для швидкої зміни валют місцями (наприклад, USD ↔️ UAH), щоб не вводити дані заново для зворотного підрахунку.
4. Як користувач, я хочу бачити попередження при введенні від’ємного числа або тексту замість цифр, щоб уникнути помилок у розрахунках.
5. Як користувач, я хочу бачити історію останніх 5 конвертацій, щоб мати змогу швидко звірити попередні підрахунки.

4. Реалізація (Псевдокод ключової функції перерахунку)

ФУНКЦІЯ конвертувати_валюту(сума, курс):
    ЯКЩО сума <= 0 АБО курс <= 0 ТОДІ
        ВИВЕСТИ «Помилка: сума та курс мають бути більшими за нуль»
        ПОВЕРНУТИ
    КІНЕЦЬ ЯКЩО

    результат = сума * курс
    результат = ОКРУГЛИТИ(результат, до 2 знаків після коми)

    ЗБЕРЕГТИ_В_ІСТОРІЮ(сума, курс, результат)
    ВИВЕСТИ результат
КІНЕЦЬ ФУНКЦІЇ
5. Тестування

1. Коректний розрахунок: Введення суми 100 та курсу 41.5 → система виводить результат 4150.00.
2. Введення від’ємного числа або нуля: Введення суми -50 або курсу 0 → з’являється повідомлення про помилку, розрахунок не виконується.
3. Порожні поля / некоректні символи: Спроба натиснути «Розрахувати» з порожнім полем курсу або введеними літерами (abc) → програма блокує дію та просить ввести коректне число.

6. Висновок

Для розробки цього проєкту найкраще підходить модель Waterfall (Каскадна модель), оскільки вимоги до конвертера валют є простими, чіткими та навряд чи змінюватимуться в процесі роботи. Невеликий обсяг функціоналу дозволяє послідовно пройти всі етапи (від проєктування інтерфейсу до тестування формули розрахунку) без необхідності постійних ітерацій чи складного планування.

Підказка для здачі: не забудьте накидати на листочку або в Paint два прості прямокутники-екрани за описом з 3-го пункту, назвати картинку prototype.png і завантажити її в папку з лабораторною на GitHub. Якщо потрібно згенерувати схематичне зображення прототипу, напишіть!
